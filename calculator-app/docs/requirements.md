## 1. 背景与目标

做一个打开即用、无需安装、无后端依赖的响应式计算器 Web App，覆盖日常四则运算、百分比、负数、括号与历史记录。桌面端优先键盘操作，手机端优先大按钮触控。

**目标**

1. 新用户无需说明，10 秒内完成一次计算（例如 `3 + 4 × 2 = 11`）。
2. 运算语义可预测、可测试、有明确文档，不依赖 `eval` 或运行时脚本求值。
3. 页面加载后不发起任何网络请求，不上报任何数据。
4. 320px 宽度起可用，桌面与手机共用一套代码。
5. 实现与测试零 npm 依赖，降低供应链与安装风险。

**非目标**

- 不做科学计算器、单位换算、财务计算器或可编程计算器。
- 不做账号、云同步、服务端计算或数据分析。
- MVP 不追求任意精度小数，精度边界在本文与架构文档中明确说明。

### 4.2 常见交互模式（未经官方核实，仅供取舍）

| 模式 | 常见表现（未能联网核实） | 优点 | 代价 | 本产品取舍 |
| --- | --- | --- | --- | --- |
| 立即执行（四则计算器） | 每按一次运算符就结算上一步，`3 + 4 × 2` 得 14 | 与实体计算器一致，单行显示简单 | 不符合数学优先级，中间结果不可见 | **不采用** |
| 表达式 + 优先级 | 输入完整表达式，`3 + 4 × 2` 得 11 | 结果符合数学直觉，可回看表达式 | 需要分词、解析与错误定位 | **采用** |
| 百分号上下文语义 | 部分四则计算器中 `50 + 10%` 可能得 55（取左值的 10%），而 `50 × 10%` 得 5 | 符合「加价/折扣」直觉 | 语义随运算符变化，难解释、难测试 | **不采用**；MVP 统一按 `/100` |
| 记忆键 MC/MR/M+/M- | 独立记忆寄存器 | 连续分段计算方便 | 增加状态与 UI 复杂度 | MVP 不做 |
| 历史磁带 | 记录已完成的表达式与结果 | 可回看、复用 | 需要持久化与容量控制 | **采用**（上限 50 条） |
| CE / C 两级清除 | CE 清当前输入，C 清全部 | 精细纠错 | 初学者易混淆 | MVP 只做 AC 与退格 DEL |
| 重复按 `=` 重复上次运算 | 例如 `2 + 3 ==` 连续加 3 | 部分用户习惯 | 隐式状态多，易误解 | MVP 不做 |
| 科学函数 / 角度制 | sin、cos、log、π、e、幂 | 覆盖学习场景 | 范围膨胀、精度与模式复杂 | 明确不在范围 |

### 4.3 取舍理由

1. **选择表达式模式**：既然禁止 `eval`，就必须自建分词与解析器；解析器天然支持优先级与括号，顺带获得可解释的表达式行和更少的隐藏状态。
2. **百分号统一按后缀 `/100`**：语义单一、可写成测试、与表达式模式一致。已知这与部分四则计算器的上下文百分号不同（未能联网核实具体行为），因此列为待确认问题 OQ-1。
3. **不做记忆键与重复等号**：MVP 聚焦「输入 → 求值 → 历史」主路径，减少状态机和验收面。
4. **历史放本机**：无账号体系下，`localStorage` 足够承载 50 条记录；隐私风险最低。

## 5. 产品原则

1. **可预测**：任何按键行为都能在文档中找到定义；不出现「看情况」的隐式规则。
2. **可恢复**：错误不清空用户输入；一次 AC 或退格即可回到可编辑状态。
3. **零网络**：运行时不请求外部资源，不埋点、不远程加载字体。
4. **键盘与触控对等**：所有功能都有可点击按钮，主要功能都有键盘入口。
5. **渐进增强**：深色模式、复制结果等为 P1/P2，不阻塞 MVP 验收。
6. **不假装高精度**：明确二进制浮点边界，展示层做稳定化处理，不宣称金融级精度。

## 7. 交互语义与示例

### 7.1 运算优先级

- 一元负号 > 百分号（后缀）> `× ÷` > `+ −`。
- `× ÷` 同级从左到右；`+ −` 同级从左到右。
- 不支持隐式乘法：`2(3+4)` 应提示「不支持省略乘号，请使用 ×」。
- 不支持幂运算与科学函数（不在本期范围）。

| 输入 | 期望结果 | 说明 |
| --- | --- | --- |
| `3 + 4 × 2` | `11` | 先乘后加 |
| `12 ÷ 3 × 2` | `8` | 同级从左到右 |
| `2 − 3 − 4` | `−5` | 左结合 |
| `(1 + 2) × 3` | `9` | 括号优先 |
| `2 × (3 + 4)` | `14` | 同上 |
| `2(3 + 4)` | 错误：不支持省略乘号 | 不做隐式乘法 |
| `1 ÷ 3` | `0.333333333333333` | 15 位有效数字显示 |
| `0.1 + 0.2` | `0.3` | 展示层稳定化，内部仍为二进制浮点 |

### 7.2 百分号（MVP 约定）

`x%` 等价于 `x ÷ 100`，是后缀一元运算，可连续叠加。

| 输入 | 期望结果 | 说明 |
| --- | --- | --- |
| `50 + 10%` | `50.1` | 严格数学语义，而不是「加 10%」 |
| `50 − 10%` | `49.9` | 同上 |
| `50 × 10%` | `5` | 50 × 0.1 |
| `50 ÷ 10%` | `500` | 50 ÷ 0.1 |
| `(50 + 50)%` | `1` | 括号整体取百分数 |
| `50%%` | `0.005` | 连续除以 100 |
| `−3%` | `−0.03` | 一元负号与百分号组合 |

> **风险提示**：部分四则计算器采用上下文百分号，`50 + 10%` 可能显示 `55`（未能联网核实）。本 MVP 明确选择 `50.1`。若产品方要求对齐四则计算器，需要修改解析/求值规则并同步全部用例（见 OQ-1）。

### 7.3 一元负号与 `±`

- 一元负号只能出现在表达式开头、`(` 之后、二元运算符之后。
- 允许多个一元负号连续出现，右结合：`−−3 = 3`，`−(−3) = 3`。
- 二元减号与一元负号按位置区分：`2−−3 = 5`，`2−(−3) = 5`。
- `±` 在编辑态切换当前操作数的符号；在求值完成态对结果取反。

| 输入 | 期望结果 |
| --- | --- |
| `−2 × 3` | `−6` |
| `5 × −2` | `−10` |
| `2 − −3` | `5` |
| `− − 3` | `3` |
| `−(2 + 3)` | `−5` |
| `−3%` | `−0.03` |

### 7.4 求值后的状态行为

| 当前状态 | 用户操作 | 行为 |
| --- | --- | --- |
| 求值成功（显示结果） | 按数字 / `.` / `(` | 开始新表达式：表达式行清空，结果行由新输入替换（旧结果已写入历史） |
| 求值成功 | 按 `+ − × ÷` / `%` | 以结果为左操作数继续编辑 |
| 求值成功 | 按 `=` | 不重复上次运算，无变化 |
| 求值成功 | 按 `DEL` | 重新进入编辑态，删除原表达式最后一个字符/记号 |
| 求值成功 | 按 `AC` | 清空显示（历史和存储保留） |
| 编辑中 | 按 `=` 且表达式不完整 | 进入错误态并提示；表达式保留 |
| 错误态 | 按数字 / `AC` | 清除错误；数字开始新表达式，`AC` 回到空态 |
| 错误态 | 按 `DEL` | 删除最后一个记号并回到编辑态 |
| 错误态 | 按二元运算符 | 忽略，直到用户清除错误 |
| 空态 | 按 `=` | 无操作，不产生历史 |

**空表达式 / 零输入约定**

- 空态按数字 `0` 显示 `0`；继续按数字时替换前导 `0`（不出现 `007`）。
- 数字中间按 `.` 只允许一个小数点；在数字起始处按 `.` 自动补 `0.`。
- 不以 `=` 作为隐式 `0`：`2 +` 不会按 `2 + 0` 处理。

### 7.5 显示格式

- 小数点固定为 `.`，不使用千分位分隔符（避免复制和再次编辑歧义）。
- 最多显示 15 位有效数字；`0.1 + 0.2` 显示 `0.3`。
- 绝对值 `>= 1e16` 或 `0 < |x| < 1e-6` 时使用科学计数法，如 `1.5e+16`、`1e-7`。
- 负零显示为 `0`。
- 结果不使用 `Infinity`、`NaN`、`-Infinity` 等原始 JS 字样。
- 最小值/下溢为 0 时显示 `0`，不报错（IEEE-754 行为，见架构文档）。

## 8. 非功能需求

### 8.1 性能

- 首屏 HTML + CSS + JS 未压缩总体积目标 < 60 KB；无图片或仅使用内联 SVG/CSS 图形。
- 中端手机首次可交互目标 < 1 s；按键到界面反馈 < 50 ms；求值 < 5 ms（表达式上限内）。
- 历史最多 50 条，渲染不得明显卡顿；不在每次按键时重写 `localStorage`。
- 不使用外部字体，采用系统字体栈。

### 8.2 可靠性

- 任何用户输入都不得导致未捕获异常或白屏。
- 解析层、求值层对非法输入必须返回结构化错误，不抛出到事件循环。
- 本地存储读写在 `try/catch` 内；JSON 损坏时丢弃并重新开始，不崩溃。
- 页面刷新后，历史记录应恢复；当前未完成的表达式不要求恢复。

### 8.3 安全与隐私

- 不使用 `eval`、`new Function`、`setTimeout("...")`、`innerHTML` 插入用户输入。
- 用户输入一律按文本处理（`textContent`），历史记录渲染不得注入 HTML。
- 无外部请求、无统计、无 Cookie、无账号、无 PII 上传。
- 建议部署方设置 CSP；页面内提供等价 meta 兜底（见架构文档 §12）。
- 历史记录仅保存在本机浏览器，用户可一键清空。

### 8.4 可维护性

- 计算核心（分词、解析、求值、格式化）与 DOM 完全分离，便于 `node --test` 直接测试。
- 核心模块语句覆盖率目标 ≥ 90%。
- 关键语义（优先级、百分号、一元负号、错误码、显示格式）必须有表格化测试。
- 不引入构建步骤；使用原生 ES Modules 和 JSDoc 类型注释。

### 8.5 兼容性矩阵

| 浏览器 | 最低版本（建议） | 说明 |
| --- | --- | --- |
| Chrome / Edge（桌面 + Android） | 最近两个稳定版本 | 主目标 |
| Safari / iOS Safari | 16.4+ | 覆盖 ES Modules、`crypto.randomUUID`、`dvh` |
| Firefox | 最近两个稳定版本 | 键盘 `/` 需阻止快速查找 |
| 不支持 | IE、旧版 EdgeHTML | 明确不做 |

> 若实际目标浏览器更旧，需在实现前确认并调整（例如 `randomUUID` 降级、`dvh` 回退）。

## 9. 验收条件（Definition of Done）

以下条件全部满足才视为 MVP 通过：

| ID | 验收场景 | 通过标准 |
| --- | --- | --- |
| AC-1 | 优先级与括号 | `3+4×2=11`、`12÷3×2=8`、`2−3−4=−5`、`(1+2)×3=9`、`2(3+4)` 提示隐式乘号错误 |
| AC-2 | 小数与显示 | `0.1+0.2` 显示 `0.3`；`1÷3` 显示 15 位有效数字；负零显示 `0` |
| AC-3 | 百分号 | §7.2 六条用例全部通过，特别确认 `50+10%=50.1` |
| AC-4 | 一元负号 / `±` | §7.3 六条用例全部通过；`±` 在编辑态与结果态行为符合定义 |
| AC-5 | 错误与恢复 | `5÷0`、`0÷0` 显示「不能除以零」；`2+` 按 `=` 提示不完整；`(1+2` 提示括号不匹配；错误后数字/AC/DEL 均可恢复 |
| AC-6 | 键盘 | 数字、运算符、括号、`%`、`Enter`、`=`、`Backspace`、`Escape`、`F9` 均按映射生效；输入法组合期间不误触；`/` 不触发浏览器快速查找 |
| AC-7 | 历史 | 成功计算后出现记录；刷新后仍在；上限 50；点击载入表达式；清空需确认 |
| AC-8 | 存储降级 | 禁用 `localStorage` 或写入抛错时，页面正常、历史仅本次会话可用、出现一次性提示 |
| AC-9 | 响应式 | 320 / 375 / 768 / 1440 宽度无页面横向滚动；触控目标 ≥ 44×44；iPhone 安全区不被遮挡 |
| AC-10 | 可访问性 | 仅用键盘可完成一次计算；焦点可见；结果通过 `aria-live` 播报；错误可被读屏读出；对比度达 AA |
| AC-11 | 安全与隐私 | 源码无 `eval` / `new Function` / 字符串定时器；Network 面板无第三方请求；历史内容不能注入 HTML |
| AC-12 | 上限与异常 | 15 位有效数字、128 字符表达式、16 层括号、50 条历史的上限均生效；超限不崩溃 |
| AC-13 | 兼容性 | Chrome / Edge / Firefox / Safari（含 iOS）最近两个版本冒烟通过 |
| AC-14 | 零依赖 | 安装与运行不需要 `npm install`；`node --test` 在 Node 22 直接通过 |

**人工验收补充**

- 真机检查：iPhone Safari、Android Chrome 至少各一台；桌面 Chrome + Safari 或 Firefox。
- 读屏：VoiceOver 或 NVDA 至少一种，确认结果与错误播报不重复、不刷屏。
- 断网/离线：页面已加载后断网，计算与历史仍可用；不出现控制台网络错误。

## 10. 明确不在范围（MVP 不做）

以下功能**本期明确不做**，实现时不得顺手加入；如要加入须新开需求与验收：

1. 科学计算：幂、开方、三角函数、对数、阶乘、常数 π/e、角度/弧度切换。
2. 单位换算、汇率、日期计算、财务函数（贷款、复利、税）。
3. 记忆键（MC / MR / M+ / M− / MS）与独立记忆寄存器。
4. 立即执行模式、上下文百分号（`50+10%=55` 一类）、重复按 `=` 重复运算。
5. CE（清除当前输入）与 C 的两级清除；MVP 只有 AC + DEL。
6. 程序员模式（十六进制、二进制、位运算）、分数/符号计算、矩阵。
7. 任意精度 / BigDecimal / 十进制库；金融或法定计量用途。
8. 历史跨设备同步、账号体系、云存储、分享链接。
9. PWA 安装、Service Worker、离线缓存策略（页面加载后无网络请求不等于可离线首次加载）。
10. 多语言、本地化小数逗号、时区/日期格式。
11. 手动主题切换、皮肤、字号设置（仅保留系统深色模式 P1）。
12. 复制/粘贴表达式、结果分享、语音输入、手写输入。
13. 原生 App（iOS/Android/桌面）、浏览器扩展、命令行版本。
14. 用户行为分析、错误上报、A/B 测试等任何远程通信。

## 11. 假设、依赖与风险

### 11.1 假设

- 产品接受「表达式模式」而非实体四则计算器的手感。
- 产品接受百分号严格按 `/100`（OQ-1 待确认）。
- 产品接受 15 位有效数字的展示精度，不要求金融级十进制精度。
- 历史记录只存在当前浏览器；换设备/清缓存即丢失。
- 部署环境支持静态文件与相对路径；HTTPS 由部署方提供。
- 实现阶段由其他 worker 负责，本阶段只交付文档。

### 11.2 依赖

- Node 22+（仅测试与本地静态服务器；运行时不依赖 Node）。
- 浏览器原生 ES Modules、`localStorage`、`Intl`（可选，不作硬依赖）。
- `node --test`（本容器已验证）。

### 11.3 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 百分号语义与用户预期不一致 | 中高：`50+10%` 被期待为 55 | OQ-1 由产品拍板；先按严格 `/100` 实现并用测试锁定；后续可作为设置项 |
| 二进制浮点显示引发「算错」投诉 | 中：如 `0.1+0.2`、大数末位 | 15 位有效数字稳定化；文档声明精度边界；测试覆盖 |
| 无浏览器自动化测试 | 中：UI 回归靠人工 | 核心逻辑全部纯函数化 + reducer 测试；提供人工清单与设备矩阵 |
| 键盘快捷键与浏览器冲突 | 低：`/` 快速查找、Backspace 后退 | 仅处理已映射按键并 `preventDefault`；忽略输入法与修饰键 |
| `localStorage` 不可用 | 低：隐私模式/配额 | 内存降级 + 提示；写入异常捕获 |
| 调研受限导致交互假设偏差 | 中：与主流产品细节不一致 | 文档明确标注「未能联网核实」；以本文件显式约定验收；需产品确认 |
| 多 worker 并行改同一目录冲突 | 中 | 本阶段仅新增 `docs/`；实现阶段按文件所有权拆分 |
| 范围蔓延（科学函数、记忆键等） | 中 | §10 明确排除；新需求走变更流程 |
